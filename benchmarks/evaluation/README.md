# Evaluation Protocol

This directory defines the provenance contract for benchmark evaluations. The purpose is to make every reported comparison auditable rather than presenting Precision, Recall, or F1 as context-free numbers.

## Benchmark tracks

| Track | Corpus role | Ground Truth source | Primary use |
|---|---|---|---|
| `synthetic` | Controlled vulnerable/fixed fixtures | Repository metadata and declared invariants | Detector diagnosis and deterministic regression |
| `adversarial` | Negative controls and attack variants | Versioned manifests with expected presence/absence | False-positive resistance and variant coverage |
| `real_world` | Independently documented deployed-contract incidents | External incident references, repository commits, and adjudicated affected locations | External validity and realistic error measurement |

The current LLM runner evaluates the `adversarial` track. The `synthetic` track is evaluated by `benchmarks/run_benchmark.py`. The `real_world` track is documented in [`benchmarks/real_world/README.md`](../real_world/README.md), with ten quarantined candidates in [`registry.json`](../real_world/registry.json) and separate adjudication records. The Real-World negative-control track is evaluated by `benchmarks/real_world/run_negative_controls.py`. The candidates are intentionally excluded from metrics until independent provenance and adjudication are complete.

## Baseline comparison

The isolated cross-track report is generated by `benchmarks/run_track_baseline.py` and documented in [`BASELINE_RESULTS.md`](BASELINE_RESULTS.md). It reports the Synthetic primary metrics, supplementary controls and variants, Real-World negative controls, quarantined Real-World candidates, and the experimental LLM comparison without merging their denominators. The Real-World adjudication contract is defined by [`adjudication.schema.json`](../real_world/adjudication.schema.json), and [`adjudication_template.json`](../real_world/adjudication_template.json) provides the required record shape.

## Required LLM run provenance

Each run must record the following fields in the schema at [`evaluation_run.schema.json`](evaluation_run.schema.json):

| Field | Requirement |
|---|---|
| `run_id` and `timestamp_utc` | Unique run identifier and UTC execution time |
| `track` | One of `synthetic`, `adversarial`, or `real_world` |
| `corpus.manifest_paths` | Exact manifests used for case selection |
| `corpus.source_sha256` | SHA-256 for every source file analyzed |
| `ground_truth` | Definition and provenance policy; never inferred from model output |
| `llm.model` | Exact model identifier from the live catalog |
| `llm.catalog_checked` | Confirmation that the live model catalog was queried |
| `llm.prompt_version` and `prompt_sha256` | Version and hash of the exact system prompt |
| `llm.temperature` | Numeric value or `null` when omitted from the request |
| `llm.max_completion_tokens` | Exact output budget sent to the endpoint |
| `llm.response_schema_version` | Version of the structured response contract |
| `cases` | Expected labels, deterministic predictions, model predictions, rationale, usage, and errors |

The runner uses `prompt_v1.txt`, JSON-schema structured output, an explicit detector enum, and an omitted temperature parameter. Omitted temperature is recorded as `null`; it must not be silently reported as zero.

## Ground Truth policy

Ground Truth is established before model execution. For the controlled and adversarial tracks, expected detector presence or absence comes from versioned repository manifests. For the future real-world track, a case must include an external reference, source commit or immutable source snapshot, affected contract/function, vulnerability classification, and an adjudication record. Analyzer findings and LLM predictions are observations; they cannot create or modify Ground Truth.

A real-world case is rejected from the corpus when the source version cannot be identified, the incident reference does not support the claimed vulnerability, or the affected location cannot be mapped to the analyzed source. Ambiguous cases should be retained in a quarantine file rather than silently labeled clean or vulnerable.

## Metrics

For every case-level assertion:

```text
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
F1        = 2 * precision * recall / (precision + recall)
```

`Inconclusive`, failed API calls, unavailable source, and unresolved Ground Truth are reported separately. They are not converted into FP, FN, or true negatives.

## Reproduction

From the repository root:

```bash
PYTHONPATH=. python benchmarks/run_llm_comparison.py \
  --model gpt-5-mini \
  --json-out llm-evaluation.json
```

The command verifies the model against the live catalog, hashes the prompt and corpus sources, records UTC provenance, and writes a JSON report. Validate the report against `evaluation_run.schema.json` before using its metrics in a document or release note.
